\# NCEP – Neuro Cardiac Electrophysiology Platform

NCEP (Neuro Cardiac Electrophysiology Platform) is an ECG processing and reporting platform designed to transform ECG recordings into standardized ECG data, process the signals using signal-processing modules, and generate structured technical reports.

\## Overview

The platform provides an end-to-end workflow for ECG data processing:

\`\`\`text

ECG File Upload

↓

Format Detection

↓

ECG Parsing

↓

Metadata Extraction

↓

Validation

↓

Canonical ECG Representation

↓

Artifact Storage

↓

Signal Processing

↓

Report Generation

↓

HTML / PDF Report

The system separates ECG ingestion, signal processing, reporting, and storage components so that each stage can be independently developed, tested, and validated.

**Key Features**

**ECG Data Ingestion**

The ingestion pipeline provides:

- File upload and validation
- ECG format detection
- Format-specific parsing
- Metadata extraction
- ECG signal validation
- Canonical ECG record creation
- Artifact generation
- Artifact manifest creation
- Persistent ECG record storage

**Supported ECG Formats**

The current ingestion architecture includes parsers for:

- WFDB
- CSV
- XML
- DICOM
- SCP-ECG

**Canonical ECG Representation**

After parsing, ECG recordings are converted into a standardized internal representation used by downstream processing components.

The canonical representation provides consistent access to:

- ECG waveform data
- Sampling frequency
- Lead information
- Signal duration
- Units
- Patient and clinical metadata where available
- Processing metadata

**Artifact Management**

The platform maintains ECG-related artifacts through a dedicated artifact storage and repository layer.

Artifacts include:

- Original ECG files
- Canonical waveform data
- Waveform metadata
- Processing artifacts
- Artifact manifest
- Checksums for artifact verification

This provides traceability between the uploaded ECG and the data used by downstream processing.

**Signal Processing Integration**

The reporting pipeline consumes measurements produced by the existing ECG signal-processing module.

The integration follows:

Canonical ECG

↓

Waveform Reader

↓

Signal Processing

↓

Signal Processing Result

↓

Report Generation Context

↓

Report

Signal-processing functionality includes analysis related to:

- P-wave
- QRS complex
- T-wave
- QT / QTc
- Tpeak-Tend
- SAECG
- Signal quality and processing information

The reporting layer consumes the results generated by the signal-processing module and does not independently recreate signal-processing algorithms.

**Report Generation**

The reporting module converts validated ECG and signal-processing information into structured reports.

The reporting pipeline includes:

- Generation context construction
- Signal-processing result integration
- Report section builders
- HTML report generation
- PDF report generation
- Technical information and processing provenance

**Detailed Report**

The Detailed Report provides:

- Executive ECG summary
- Conventional ECG measurements
- Atrial electrophysiology information
- Ventricular electrophysiology / SAECG information
- Repolarization analysis
- Integrated technical information
- Processing and provenance information

The report uses a consistent visual design and is generated in A4 format.

**Reliability and Processing**

The platform includes job-based processing for long-running ECG operations.

The ingestion workflow supports:

- Asynchronous processing
- Persistent processing jobs
- Idempotent ingestion
- Job status tracking
- Retry handling
- Artifact verification
- Failure handling
- Report-generation job tracking

This prevents long-running ECG processing operations from depending entirely on a single synchronous HTTP request.

**Data Integrity**

The platform maintains traceability across the ECG processing pipeline:

Uploaded ECG

↓

Parsed ECG

↓

Canonical ECG

↓

Stored Artifacts

↓

Signal Processing

↓

Report Generation

Artifact manifests and checksums are used to verify stored ECG artifacts.

The reporting layer consumes signal-processing results while preserving the source values and applying only approved presentation-level transformations such as formatting and unit conversion.

**Validation and Testing**

The project includes validation at multiple levels:

- Parser validation
- ECG signal validation
- Artifact validation
- API validation
- Signal-processing integration validation
- Report-generation validation
- HTML report validation
- PDF generation validation
- End-to-end ECG workflow validation

The complete workflow has been validated using real ECG data through the ingestion, signal-processing, and report-generation pipeline.

**Design Principles**

**Separation of Responsibilities**

The platform separates:

ECG Ingestion

↓

Signal Processing

↓

Report Generation

Each layer has a defined responsibility.

**Signal Processing**

Responsible for ECG signal analysis and generation of processing measurements.

**Reporting**

Responsible for consuming processing results and presenting them in structured human-readable reports.

**Storage**

Responsible for maintaining ECG records, processing artifacts, and artifact integrity.
